# Архитектура To-Do List

## Назначение приложения

Приложение позволяет вести список дел с названием, сроком выполнения и статусом. Пользователь работает с задачами через консольное меню, а данные сохраняются в JSON-файле `tasks.json`.

## Модули проекта

### `main.py`

Точка входа приложения. Загружает задачи из хранилища, создаёт объект `TaskManager`, передаёт его в `ConsoleUI` вместе с функцией сохранения и запускает интерфейс.

### `logic.py`

Содержит бизнес-логику приложения:
- класс `Task` описывает отдельную задачу;
- класс `TaskManager` управляет списком задач;
- методы менеджера добавляют, удаляют, завершают, фильтруют и ищут задачи;
- исключения `ValueError` используются для обработки некорректных данных и отсутствующих задач.

### `ui.py`

Содержит класс `ConsoleUI`. Он выводит меню, принимает пользовательский ввод, отображает задачи и вызывает методы `TaskManager`. После изменения списка интерфейс вызывает переданную функцию сохранения.

### `storage.py`

Содержит функции `load_tasks()` и `save_tasks()` для чтения и записи задач в JSON-файл `tasks.json`. Отдельный класс хранилища в текущей версии не используется.

### `test_logic.py`

Содержит автоматические модульные тесты для классов `Task` и `TaskManager`, включая проверку валидации, изменения статуса, добавления, удаления, фильтрации и поиска.

## Взаимодействие компонентов

```text
                 main.py
                    |
          +---------+----------+
          |                    |
      storage.py           ConsoleUI
          |                    |
       Task                 TaskManager
                               |
                              Task
```

При запуске `main.py` загружает сохранённые задачи и передаёт их менеджеру. Интерфейс обращается к менеджеру для выполнения операций. После добавления, завершения или удаления задачи вызывается функция сохранения из `storage.py`.

## Проверка качества

Автоматические тесты запускаются командой:

```bash
python -m unittest -v
```

В репозитории также настроен GitHub Actions workflow в `.github/workflows/tests.yml`, который автоматически запускает тесты при отправке изменений в рабочую ветку и при pull request.

## Запуск приложения

Требуется Python 3.10 или новее. Из корневого каталога проекта выполните:

```bash
python main.py
```
