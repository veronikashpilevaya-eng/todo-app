# Диаграмма классов и описание

## Task
Класс отдельного дела. В проекте реализован в модуле `logic.py`.
- `title: str` — название дела.
- `deadline: str` — срок выполнения.
- `done: bool` — признак выполнения.
- `mark_done(): None` — отмечает дело выполненным.
- `__str__(): str` — возвращает текстовое представление дела.

## TaskManager
Логическая роль управления коллекцией дел.
- `tasks: list` — список объектов `Task`.
- `add_task(task: Task): None` — добавляет дело.
- `remove_task(title: str): None` — удаляет дело.
- `get_all(): list` — возвращает все дела.
- `find_by_title(title: str): Task` — ищет дело по названию.

В текущей реализации операции менеджера представлены функциями в `logic.py` (`add_task`, `mark_task_done`, `delete_task`), а не отдельным классом.

## TaskStorage
Логическая роль слоя хранения данных.
- `filename: str` — имя файла хранения.
- `load(): list` — загружает дела.
- `save(tasks: list): None` — сохраняет дела.

В текущей реализации операции хранения представлены функциями `load_tasks()` и `save_tasks()` в модуле `storage.py`. Данные записываются в `tasks.json`.

## ConsoleUI
Логическая роль консольного интерфейса.
- `manager: TaskManager` — объект управления делами.
- `run(): None` — запускает меню.
- `print_menu(): None` — выводит меню.
- `print_tasks(): None` — выводит список дел.

В текущей реализации интерфейс представлен функциями в `ui.py`, прежде всего `run_app()` и `print_menu()`.

## Связи между классами
1. `ConsoleUI --> TaskManager` — ассоциация: интерфейс обращается к логике управления делами.
2. `TaskManager o-- Task` — агрегация: менеджер содержит коллекцию объектов дел.
3. `TaskManager ..> TaskStorage` — зависимость: менеджер использует хранилище при сохранении и загрузке.
4. Прямая связь `TaskStorage` с `ConsoleUI` отсутствует. Слой интерфейса не должен напрямую управлять файлами.

## Примечание о реализации
Диаграмма показывает целевую объектную модель, требуемую заданием. В существующем учебном приложении уже реализован класс `Task`, а обязанности `TaskManager`, `TaskStorage` и `ConsoleUI` пока распределены между функциями модулей `logic.py`, `storage.py` и `ui.py`. Это позволяет сохранить работающую программу и использовать диаграмму как проектное описание дальнейшего развития.
